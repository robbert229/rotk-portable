# ROTK decompilation roadmap

Master plan for decompiling **The Lord of the Rings: The Return of the King** (EA, 2003, PC)
and turning it into a portable source port. It is written to be **sliced into independent
work packages (WPs)** and handed to many agents in parallel.

- **Orchestrators:** pick WPs whose `Depends on` are all `done`, fill the brief template in
  [`agent-playbook.md`](agent-playbook.md#brief-template), and update the **Status board** below
  when the agent reports back. Only the orchestrator edits this file.
- **Agents:** read [`AGENTS.md`](../AGENTS.md) → [`agent-playbook.md`](agent-playbook.md) → your WP
  section here → the specs it links. Do not edit this file; report status in your handoff.

Evidence tags (**observed / inferred / unknown**) apply to this document too. Everything
about the *unpacked* exe below is **inferred** until M1 lands.

---

## 1. North star and milestones

**End state:** a C source tree in this repo that builds a native 64-bit executable for
Windows, Linux and macOS, loads assets from the **user's own** retail install or ISOs, and
plays the game end-to-end. No original assets or original binary ever ship with the repo.

| ID | Milestone | Definition of done | Gate type |
|---|---|---|---|
| **M0** | Foundations | Corpus manifest, test harness, symbol DB, headless Ghidra pipeline, Rich-header facts all in repo. **Reached 2026-11-22** (PRs #1–#8); follow-ups 0.9–0.13 open | agents |
| **M1** | Unpacked image | `ROTK_unpacked.exe` (local only) passes `tools/validate_dump.py`; zero live xrefs from `.text` into SafeDisc sections | **human** (Windows VM) |
| **M2** | Mapped binary | Every function is assigned to a source unit (`.c` file) or a library; ≥ 60 % of non-library functions carry a real name | agents |
| **M3** | Formats complete | Every file in `Data/` parses with a stdlib tool; no **unknown** field in a spec that the exe reads | agents |
| **M4** | Hooked hybrid | `rotk_hook.dll` replaces original functions at runtime; game plays start → credits with ≥ 50 % of game-code functions reimplemented | agents + human playtest |
| **M5** | Standalone | 100 % reimplemented; links into its own exe; original `ROTK.exe` no longer loaded. Still Win32 / D3D8-shaped | agents + human playtest |
| **M6** | Portable | SDL-based platform layer, modern renderer and audio, 64-bit clean, CI builds on 3 OSes | agents |

## 2. Strategy decisions

Each decision has a recommendation. **OPEN** items need the owner's sign-off before the
listed WPs start. Agents must not decide these.

| ID | Decision | Recommendation | Blocks | Status |
|---|---|---|---|---|
| **D-1** | Matching decomp (byte-identical recompile) vs. functional equivalence | **Byte-matching is the per-function target.** Compiler: [`archaic-msvc/msvc700`](https://github.com/archaic-msvc/msvc700) pinned at `97fe4cdeaeb0bb934591d4b05eb52c2e8ab3e34b` (cl **13.00.9466**, identical to the Rich header, **observed**). It is cloned by script into gitignored `out/toolchain/msvc700/` and never committed. A function that can't be matched may land only with an equivalence-harness test and a `/* NONMATCHING: <reason> */` note and symdb status `nonmatching`. | P5 | **accepted** 2026-11-10 |
| **D-2** | Implementation language | **C (C99 subset)**, mirroring the original (all recovered source paths are `.c`, **observed**). It must compile under MSVC, clang and gcc. | P5 | proposed |
| **D-3** | Replacement strategy | **Incremental hooking** (re3/reVC model): an injected DLL replaces original functions one at a time, so the game stays playable and every function is testable in the real process. A big-bang rewrite has no test oracle until the very end. | WP-5.0+ | proposed |
| **D-4** | Tooling-language exceptions | Keep `tools/` stdlib-only. Allow **`re/ghidra/`** scripts (PyGhidra/Java run inside Ghidra) and a two-layer build. A **top-level `Makefile`** (GNU make) is the single front door: toolchain fetch, configure, build, compare, test. **CMake** does the actual build of `src/`, via presets for each toolchain. For the matching preset, CMake's C compiler and linker are thin shims that call `tools/msvc.py`, which runs cl/link 13.00.9466 under Wine. `AGENTS.md` amended. | WP-0.3, 0.4, 5.0 | **accepted** 2026-11-10 |
| **D-5** | Source of truth for RE knowledge | **Text files in the repo** (`re/symbols/*.csv`, `re/types/*.h`, `re/units.csv`). The Ghidra project stays local and gitignored, and is rebuilt from those files by script. Ghidra projects can't be merged and contain copyrighted code. | P2, P3 | proposed |
| **D-6** | Publishing decompiled C | **Reconstructed C source is published.** It must be written in the repo (human or agent authored, annotated with original addresses). Never commit original bytes, dumped/unpacked exes, raw decompiler or disassembly listings, game assets, or the Microsoft toolchain. Users supply their own game copy. | P5 | **accepted** 2026-11-10 |
| **D-7** | M6 renderer / audio / video backends | Renderer: abstraction over **SDL3 GPU** (or bgfx). Audio: **OpenAL Soft** (EFX can approximate EAX 3 reverb). Video: **FFmpeg libavcodec** (MPEG-4 ASP) behind the existing `LLVideo` seam. Decide at P7 start. | P7 | deferred |

## 4. Phases and work packages

Sizing: **S** fits in one agent session · **M** takes 1–3 sessions · **L** must be split
into tickets before an agent starts it.
`Human` = needs the owner (hardware, a Windows VM, a playtest, a purchase or a decision).

### Phase 0 — Foundations (no exe needed; start now)

#### WP-0.1 Corpus manifest · S · **done** (#1; `.pac` check pending ISOs)
- **Goal:** a hash list of every original file, so all later work can cite exact inputs.
- **Deliverables:** `tools/corpus.py` (walk the install dir and optionally the ISOs plus `.pac` members via `unpac.py`) → `re/corpus/manifest.csv` (`origin,path,size,sha256`).
- **Accept:** deterministic output across two runs; `ROTK.exe` hash equals the README; the 83 `.pac` members match `Data/` hashes; writes nothing into the game prefix.
- **Delivered:** 120 install rows, deterministic, ROTK.exe hash matches (**observed**, PR #1). The `.pac` mode is tested only on a synthetic archive; the 83-member comparison waits for `$ROTK_ISO_DIR` (follow-up WP-0.10).

#### WP-0.2 Regression test harness · S · **done** (#2)
- **Deliverables:** a `test` target in the top-level `Makefile`; `tests/test_tools.py` (unittest) runs `scwdump`, `geo2obj`, `txw2png` and `unpac` against `assets/samples/` and asserts the SHA-256 of their output. Every test skips cleanly when samples are missing. Expected hashes live in `tests/expected.json`.
- **Accept:** `python3 -m unittest discover tests` passes with samples present and reports skips (no failures) on a clean clone.

#### WP-0.3 Symbol database schema + tools · M · **done** (#3, #8)
- **Deliverables:** `re/README.md` (schema), `tools/symdb.py` (`lint`, `merge`, `stats`, `export-ghidra`, `export-hooks`). CSV columns: `address,size,name,unit,module,kind(func|data|vtable|lib),signature,status(auto|named|typed|decomp|verified|nonmatching),evidence`.
- **Delivered:** `nonmatching` (accepted under D-1) marks a decompiled function that passes its equivalence test but does not byte-match. Units are module-qualified paths without extension (`Kernel/EntityManager`). `export-ghidra` writes `address,size,name,kind,signature`; `export-hooks` writes `address,name,signature,enabled_by_default` for `decomp|verified|nonmatching` rows. Lint also rejects names reused across modules and C/MSVC keywords (#8). Spec: [`re/README.md`](../re/README.md).
- **Accept:** lint rejects duplicate or overlapping addresses, bad names and missing evidence; merge of two module files is conflict-free; `stats` prints the % named / typed / decomp per module.

#### WP-0.4 Headless Ghidra pipeline · M · **partial** (#4)
- **Inputs:** Ghidra 12.1.4 at `~/.local/opt/ghidra/ghidra_12.1.4_PUBLIC` (**observed**); `GHIDRA_HOME` env var.
- **Deliverables:** `tools/ghidra_build.py` (stdlib, shells out to `support/analyzeHeadless`) builds `out/ghidra/ROTK.gpr` from a given exe, applies `re/ghidra/ImportSymbols.py` and `ImportTypes`, and runs `ExportSymbols.py` to refresh auto-entries.
- **Accept:** one idempotent command; works now on the packed exe (expect around 58 functions, **observed** earlier) and later on the dump; symbols survive a round trip unchanged.
- **Delivered:** `make ghidra` / `make ghidra-export`; scripts are Java (`re/ghidra/*.java`), not Python. The packed exe yields **48** functions under this headless analysis (**observed**, PR #4; the earlier 58 came from a different analysis run, cause **unknown**). Export writes unassigned candidates to `out/ghidra/unassigned.csv` instead of editing `re/symbols` in place. Not done: `ImportTypes` (moves to WP-2.4, when `re/types/` exists) and a real round-trip test (follow-up WP-0.11). See [`re/ghidra/README.md`](../re/ghidra/README.md).

#### WP-0.5 Pre-unpack string and source-path inventory · S · **done** (#5)
- **Goal:** seed the module map from what is already readable in the packed image.
- **Deliverables:** `re/strings/source_paths.txt` (every distinct `f:\EAThirdPerson\...` / `C:\Dev\...` path, normalised, with hit counts) and `docs/modules/README.md` (module tree, expected unit count per module).
- **Accept:** every path appears exactly once, with file offsets; the module tree matches the README module list or explains the differences.
- **Delivered:** 73 distinct paths, 71 `.c`, 8 `LL*_Win.c` platform files (**observed**). Four top-level directories missing from the old README list (`Audio`, `IGC`, `SPECIF`, `Stream`); `Memory_Card` sits beside `LL`, not under it. See [`docs/modules/README.md`](modules/README.md).

#### WP-0.6 Rich header and toolchain fingerprint · S · **partial** (#6; CRT share needs M1)
- **Already observed (2026-11-10, ad hoc decode):** ROTK.exe = Utc13_C 13.00.9466 ×563 objects, Utc13_CPP 9466 ×10, Masm700 ×43, Linker700/Export700/Cvtres700 9466, plus 13.00.9178 C ×4 / C++ ×12 (prebuilt static lib, **inferred**) and small VC6-era items (prodid 11 b8799, 18 b8444). Helpers `eauninstall.exe` and `rotk_uninst.exe`: same 9466 toolchain. 563 is an **upper bound** on game `.c` units, because static CRT objects count too. Remaining work: the committed tool, checksum validation, and subtracting the CRT object share (count the `libcmt.lib` members that get linked).
- **Goal:** pin exact compiler/linker build numbers. The `@comp.id` counts give the number of C objects (≈ translation units).
- **Deliverables:** `tools/richhdr.py` (decode the XOR-masked Rich header and map prodid/build to tool names) and a results section in the README toolchain block, for `ROTK.exe`, `eauninstall.exe` and `rotk_uninst.exe`.
- **Accept:** checksum validates, or the header is shown to be absent or damaged by SafeDisc (**observed**, with offsets). The number of C objects is reported as the expected unit count, cross-checked against WP-0.5.
- **Delivered:** `tools/richhdr.py` + `make richhdr`; ROTK.exe's checksum validates (**observed**). 563 is the total for the 9466 C batch; the reference `libcmt.lib` has 543 such members but which ones were linked is **unknown** pre-dump, so the estimate is **71–562 game C units** (**inferred**). 13.00.9178 is labelled the Windows XP SP1 DDK compiler by richprint (**observed**, provenance of those objects **unknown**). Results live in [`docs/research/toolchain.md`](research/toolchain.md). Remaining: narrow the range after M1 (count linked CRT functions in the dump).

#### WP-0.8 Compiler setup and flag recovery · M · setup **done** (#7, #8); flag confirmation after M1
- **Goal:** run cl 13.00.9466 under Wine from Linux, and recover ROTK's compile flags.
- **Inputs:** `archaic-msvc/msvc700` @ `97fe4cde…` (D-1). `$MSVC700_DIR` overrides the default `out/toolchain/msvc700/`. Pre-M1: the helper exes (same toolchain) and statically linked library code.

### Phase 1 — Unpack SafeDisc (critical gate)

Background and tool survey: [`research/safe-disc.md`](research/safe-disc.md).

#### WP-1.1 Static SafeDisc version fingerprint · S · **done** (#11)
- **Deliverables:** an addendum to `safe-disc.md` with the exact SafeDisc version (search for the `BoG_`/`SD2`-style marker and the stub signatures), plus the section-by-section role of `stxt371`/`stxt774`/`tdb`.
- **Delivered:** `BoG_` marker at file+0xFD4 with version fields 3/10/20 (**observed**), read as **SafeDisc 3.10.020** (**inferred**, BurnOutSharp layout). `SECDRV.SYS` reports 3.19.000 (**observed**). Eight sections; there is no `tdb` section, the earlier name was a misreading of a section named with eight spaces (**observed**). The OS/subsystem header fields are normal (4.0, GUI), not scrambled. Entry point at packed VA 0x009C305E in `stxt371`. Roles of `stxt774`, `.data1` and the space-named section remain **unknown**. See [`safe-disc.md` §WP-1.1](research/safe-disc.md#wp-11--static-fingerprint-of-the-retail-executable).
- **Accept:** version with offset evidence, or a documented negative with the search coverage listed.

#### WP-1.2 Dump runbook · M · **partial** (#12; rework from dry-run review in WP-1.2b)
- **Deliverables:** `docs/research/unpack-runbook.md`, a click-by-click procedure for the owner:
  - VM spec (32-bit Windows XP SP3 or 7, snapshot points)
  - SafeDiscShim vs. SafeDiscLoader2 choice
  - x32dbg + ScyllaHide settings
  - **OEP signature taken from the unprotected EA helpers.** `eauninstall.exe` and `rotk_uninst.exe` share linker 7.00 (**observed**), so their `mainCRTStartup`/`WinMainCRTStartup` byte pattern is a template for recognising ROTK's OEP (**inferred**).
  - Scylla IAT autosearch + fix-dump, and which files to copy out
- **Accept:** a dry-run review by a second agent finds no ambiguous steps; every tool has a version and URL.
- **Status:** [`unpack-runbook.md`](research/unpack-runbook.md) merged; every tool pin resolves. The dry-run review returned **needs rework**: tool staging is lost on snapshot restore, there's no installed-exe hash check, debugger stop/OEP-confirmation steps and the Scylla IAT choice are ambiguous, validation doesn't match WP-1.3, and `safe-disc.md` still links distribution listings. **WP-1.2b** applies those fixes; a second dry run closes WP-1.2.

#### WP-1.3 Dump validator · S · **done** (#13; gate alignment in WP-1.3b)
- **Deliverables:** `tools/validate_dump.py`. Checks: PE sanity; EP inside `.text`; `.text` entropy below threshold; import DLL set ⊇ {`d3d8`, `dinput8`, `dsound`, `eax`, `DivxMediaLib`, `kernel32`, `user32`, …}; count of call/jmp targets from `.text` into SafeDisc sections; size near 2,874,232 B (no-CD oracle, **observed** via PCGW).
- **Accept:** FAILS on the retail packed exe with clear reasons; PASSES the structural checks on `eauninstall.exe`; prints a JSON report.
- **Delivered:** `tools/validate_dump.py`, `make validate-dump` ([`dump-validator.md`](research/dump-validator.md)). Both acceptance checks pass. Found: the packed exe is 2,874,240 B, only 8 B from the size reference (**observed**), so size can't distinguish a dump. **WP-1.3b** makes size and `DivxMediaLib` (probably late-bound, **inferred**) advisory, and adds a strict default mode that fails on any `.text` → SafeDisc-section call/jmp (the M1 gate) plus `--pre-repair` for the raw WP-1.4 capture.

#### WP-1.4 Run the dump · **Human** · gate for M1
- **Deliverables (local only):** `out/unpacked/ROTK_unpacked.exe`, Scylla log, VM notes. Committed: `re/corpus/unpacked.sha256` and a run log in the runbook.
- **Accept:** `make validate-dump VALIDATE_FLAGS=--pre-repair` passes (residual stub calls are reported for WP-1.5). The strict default mode is the M1 gate after WP-1.5.

#### WP-1.5 Post-dump repair · M · needs 1.4
- **Goal:** no remaining dependence on SafeDisc code: redirected API thunks, stolen or emulated instructions, CD-check calls.
- **Deliverables:** `tools/fixdump.py` (deterministic patcher driven by a committed patch list with addresses and evidence) and `docs/research/dump-repair.md`.
- **Accept:** zero xrefs from `.text`/`.rdata` into SafeDisc sections; the repaired exe launches to the main menu on the VM without SafeDisc tooling.

#### WP-1.6 Run the unpacked exe under Wine · S · needs 1.5 · Human (observe)
- **Accept:** documented result: boots to menu / plays a level / crash log. This decides whether P5 hook testing can run on Linux (Wine + DXVK) or needs the VM.

### Phase 2 — Static bootstrap (needs M1)

#### WP-2.1 Analysis baseline · S
- Build the Ghidra project from the repaired dump (WP-0.4). Record function count, `.text` coverage and undefined-byte ranges in `re/stats.md`. This is the denominator for all later progress metrics.

#### WP-2.2 Library identification · M
- **Targets (inferred present):** static MSVC 7.0 CRT; **D3DX8** (statically linked in DX8 titles); `dxguid`; **libmad** (wrapped by `RCMP/rcmp_mad_codec.c`, **observed** path); possibly zlib.
- **Method:** Ghidra FID (check which bundled `.fidb` covers VC7.0); custom FIDB/signatures built from reference libraries compiled with matching flags where obtainable (R-2); string and constant anchors (libmad Huffman tables, zlib `inflate` messages, CRT error text).
- **Deliverables:** `re/symbols/lib_*.csv` with `kind=lib`; `docs/analysis/libraries.md` listing each library, version and byte range.
- **Accept:** every library function is tagged; the share of `.text` that is library code is reported.

#### WP-2.3 Source-unit partition · M
- **Method:** functions that reference a `__FILE__` path string (asserts or logging) anchor a unit. MSVC lays out object files contiguously in link order (**inferred**), so the gaps between anchors of the same unit are filled. Cross-check the unit count against WP-0.6.
- **Deliverables:** `re/units.csv` (`unit,module,start,end,anchors,confidence`).
- **Accept:** ≥ 85 % of non-library `.text` bytes are attributed; every range lists its anchor evidence.

#### WP-2.4 Platform types · S
- Generate Ghidra data types for DirectX 8 (`d3d8`, `dinput`, `dsound`), EAX and Win32 from **Wine's LGPL headers**, plus `include/rotk/*.h`. COM vtable calls must render as `IDirect3DDevice8::SetRenderState` and similar.
- **Accept:** a sample of 20 D3D call sites decompiles with method names.

#### WP-2.5 Global data map · M
- `.data`/`.rdata`/`.bss` layout: function-pointer tables (the C "vtables"), string tables, DTB descriptor tables and the large static arrays → `re/symbols/data_*.csv`.

#### WP-2.6 Boot and main-loop trace · M
- OEP → CRT → `WinMain` → engine init order → main loop → per-frame update/render → shutdown. Deliverable: `docs/analysis/boot.md` with addresses. This is the spine every later module hangs off.

#### WP-2.7 LL platform-layer inventory · S
- Every `LL*` / `*_Win.c` unit (file, memory, memory card, input, video, audio, timer, thread): function list, the API each one exposes to the engine, and the Win32/DX calls inside → `docs/analysis/ll-layer.md`. **This is the porting seam for P7** (console-first engine, PC backend swapped in, **inferred** from paths).

### Phase 5 — Decompilation via hooking (needs M2 for the module, D-1, D-3, WP-0.8)

#### WP-5.0 Source tree and build scaffold · M
- `src/` mirrors the original `code/` tree. The build has two layers (D-4).
- **CMake** (`CMakeLists.txt` + `CMakePresets.json`) is the real build. Presets:
  - `msvc700`: matching build. `cmake/toolchain-msvc700.cmake` points `CMAKE_C_COMPILER`/`CMAKE_LINKER` at the `msvc.py` shims (`out/toolchain/bin/cl`, `.../link`, generated by `msvc.py fetch`) with the WP-0.8 flags.
  - `mingw-i686` / `clang-cl`: `rotk_hook.dll` from modern compilers.
  - `native`: host gcc/clang build for P7.
  - Per-unit flag overrides are `set_source_files_properties` calls in a committed `src/flags.cmake`.
- **Makefile front door:** `make toolchain`, `make matching` (configure + build the `msvc700` preset), `make compare` (per-function byte diff vs. the dump, WP-5.2), `make hook`, `make portable`, `make test` (unittest + symdb lint). Each target is a thin wrapper over `cmake --preset` / `cmake --build` or `tools/*.py`.
- **Verify early (risk):** CMake's MSVC compiler detection and dependency scanning against cl 13.00 under Wine. Ninja's MSVC dep scanning uses `/showIncludes`; cl 13.00 supports it (**observed**, WP-0.8). Still **unknown**: whether Ninja parses its output once paths come back as Wine `Z:\` paths. If not, use the Makefiles generator or have `msvc.py` rewrite the dependency lines.
- Per-function annotation: `/* ROTK 0x0045A1C0 */` on the line before each definition.
- **Accept:** `make matching` builds a trivial unit through CMake → shim → cl 13.00.9466 (Rich entry `prodid 28 build 9466`); an empty hook DLL builds on Linux and Windows and loads into the repaired exe (proxy DLL or loader); the game still runs.

#### WP-5.1 Hook runtime · M
- Generate the hook table from `re/symbols/*.csv` (`symdb.py export-hooks`), install `jmp` patches at original entry points, and allow per-function enable/disable from a config file so a regression can be **bisected** to one function. Also provide original-function trampolines.
- **Accept:** toggling one hooked function on and off at startup is logged and changes behaviour as expected on a test function.

#### WP-5.2 Equivalence harness · M
- In-process differential testing: call the original and the reimplementation on the same fuzzed or recorded inputs and compare outputs and the memory they touch. Covers pure and leaf functions (math, Lib, parsers, DTB lookups).
- **Primary oracle (D-1): per-function byte compare.** Recompile the unit with msvc700 and the WP-0.8 flags, then diff each function against the dump. Relocations and absolute addresses are masked; the tool chosen in WP-0.8 does the diff. Reports `match` / `nonmatching (n bytes)` per function and feeds `symdb` status.
- **Accept:** ≥ 10 Lib functions byte-matched; the remaining functions are behaviour-checked by the differential harness.

#### WP-5.3 Input record/replay · M
- Deterministic input capture and replay through the `LL` input layer, plus a screenshot hash at fixed frames. This is the regression oracle for M4–M6 (**Human** records the reference runs).

#### WP-5.\<Module\>.\<Unit\> Unit decomp tickets · S each
- **One ticket = one original `.c` unit** from `re/units.csv`. That is the natural agent-sized task. Suggested module order, bottom-up: Lib → LL → Kernel → DTB → Anim → Coll/Phys → Camera → Actors → SFX → Rend → Audio/Video → UI → Game.
- **Accept per ticket:** every function in the unit is reimplemented and annotated; it builds warning-free with msvc700 and modern compilers; **every function byte-matches**, or carries `NONMATCHING` plus a passing equivalence test; hooked play-through of an affected mission shows no regression on the replay set; `symdb` status is set to `decomp`/`verified`.
